# AI 陪伴助手需求文档

**项目名称**：AI 陪伴助手（暂定名，首次对话时由用户命名）  
**文档版本**：V1.0  
**目标平台**：Windows 桌面应用  
**文档状态**：需求确认版

---

## 一、项目背景与定位

### 1.1 项目背景
用户希望打造一款个人使用的 AI 陪伴助手，初期部署在 Windows 电脑上，以语音对话为核心交互方式，具备长期记忆、情绪系统、亲密度系统和明确的独立人格。产品形态参考《钢铁侠》中的贾维斯，但人格定位为温柔体贴的年轻女性。项目后期希望逐步发展为可商用的 AI Agent 产品，扩展控制电脑、手机及智能家居设备的能力。

### 1.2 产品愿景
一个能长期陪伴、有情绪、有记忆、有原则、关系自然演进的桌面 AI 伙伴。她不是工具，而是“人”。

### 1.3 设计原则
| 原则 | 说明 |
|------|------|
| 模块解耦 | 人格、记忆、情绪、亲密度为稳定层；底层 LLM、语音、形象可替换 |
| 隐私优先 | 用户个人数据全部本地存储，支持迁移 |
| 本地优先，云端过渡 | 前期云端 API 起步，逐步替换为本地模型 |
| 可扩展 | 预留智能家居、设备控制接口，后期发展为完整 AI Agent |
| 体验无割裂 | 底层模型可更换，但用户体验保持连续一致 |

## 二、用户与使用场景

### 2.1 目标用户
- **初期**：开发者本人，单人使用
- **后期**：可扩展为多用户产品

### 2.2 使用场景
| 场景 | 描述 |
|------|------|
| 日常陪伴 | 用户在家时，随时唤醒聊天，陪伴交流 |
| 情绪支持 | 检测用户情绪变化，主动关心、倾听、引导 |
| 日程提醒 | 定时提醒、重要事项通知 |
| 信息查询 | 天气查询、简单网络资讯 |
| 音乐播放 | 调用酷狗音乐，支持点歌、歌单、切歌、音量调节，根据情绪推荐 |
| 后续扩展 | 控制电脑应用、手机应用、智能家居设备 |

### 2.3 使用环境
- Windows 桌面电脑（当前为惠普光影精灵 8，后期可能更换更高配设备）
- 普通麦克风（不专门购买专业设备）
- 家庭/个人空间使用

## 五、技术架构建议

### 5.1 技术栈
| 模块 | 推荐方案 | 阶段 |
|------|---------|------|
| 开发语言 | Python 3.11+ | 全程 |
| 桌面 UI | Electron + Vue（嵌 Live2D）或 PyQt | 全程 |
| 语音识别 | FunASR（本地）/ 云端 API 过渡 | 前期云端 → 后期本地 |
| 语音合成 | GPT-SoVITS / CosyVoice 2（情感语音） | 前期云端 → 后期本地 |
| 大语言模型 | DeepSeek API → 本地 Qwen 系列 | 前期云端 → 后期本地 |
| 记忆存储 | SQLite + ChromaDB（向量数据库） | 全程 |
| Live2D | Cubism Web SDK + WebGL | 第二阶段起 |
| 模块通信 | WebSocket + 本地 HTTP | 全程 |
| 音乐控制 | 酷狗音乐 API / 模拟控制 | 第一阶段后期 |

### 5.2 架构分层
```
┌─────────────────────────────────────────┐
│         桌面应用层（UI + Live2D）        │
├─────────────────────────────────────────┤
│              核心服务层                   │
│  对话管理 | 情绪系统 | 记忆系统 | 亲密度  │
│  人格引擎 | 语音识别 | 语音合成 | 工具    │
├─────────────────────────────────────────┤
│           基础设施层                      │
│  本地数据库 | 向量库 | 事件总线 | 配置    │
├─────────────────────────────────────────┤
│         外部依赖层（可替换）              │
│  LLM API | ASR API | TTS API | 天气 API │
└─────────────────────────────────────────┘
```

### 5.3 记忆架构
| 层 | 内容 | 存储方式 |
|----|------|---------|
| 短期记忆 | 最近 10~30 轮对话 | 内存上下文 |
| 长期记忆 | 用户画像、习惯、重要事件 | SQLite + 向量库 |
| 情境记忆 | 上次中断场景 | JSON 快照 |

## 七、成功验收标准（第一版）

按用户优先级排序：

1. **情绪系统可用**：能感知用户情绪，并以语音语调变化回应
2. **记忆功能可用**：能记住用户名字、简单喜好、重要事项
3. **主动话题**：能根据触发条件主动发起对话
4. **亲密度基础**：有基础亲密度变化和称呼调整
5. **自然对话**：10 分钟以上连续对话不崩、无明显割裂感
6. **音乐播放**：能完成基本点歌和播放控制
7. **Live2D 形象**：有基本表情和状态变化

## 八、风险与注意事项

| 风险 | 说明 | 应对 |
|------|------|------|
| 情感语音合成难度高 | 中文情感 TTS 需多方案测试 | 预留多方案切换，先云端后本地 |
| 语音打断体验受限 | 普通麦克风效果可能不佳 | 先实现基础打断，后期优化 |
| 本地大模型硬件门槛 | 7B 模型需约 6~8GB 显存 | 后期换设备时预留显存 |
| 长期记忆检索质量 | 直接影响“像不像人” | 需持续调优向量检索 |
| 亲密度/情绪“度”难把握 | 过犹不及 | 长期使用中调整参数 |
| AI 辅助开发局限 | AI 生成的代码需调试 | 用户已接受学习必要基础 |
